파이프라인

단계마다 결과 파일이 남고, 다음 단계는 그 파일만 읽습니다. 그래서 어느 단계든 따로 다시 돌릴 수 있고, 중간 파일을 열어 보면 어디서 잘못됐는지 알 수 있습니다. 각 단계의 입력, 출력, 건너뛰는 조건은 kdaa 단계별 동작에 있습니다.

배포 시에는 경로가 다릅니다. ESP32-S3에서 마이크 소리를 받아 소리로 타건 시작점을 찾고, 같은 규격의 로그멜을 만들어 int8 모델에 넣습니다. 그 결과(kdaa.afe.v1 JSON)는 LM 서버가 받아 두벌식 오토마타로 문장을 복원합니다. LM 서버는 이 네 저장소에 없습니다.

용어

session / session_uid
녹음 한 번. 디렉터리 <P>/<S>/<SESSION> 하나이고, uid는 P01_S01_SESSION01처럼 참가자·시나리오·세션 id를 이은 문자열입니다. classism은 세션 단위로 학습/검증/테스트를 나눕니다.
trial / trial_id
sound-autodaq에서 "이 키를 한 번 눌러라" 한 번. 성공하면 WAV 하나가 남습니다. 다시 녹음하면 새 trial_id를 받습니다.
clip_id
학습 데이터에서 타건 하나의 이름. export가 <session_uid>_<trial_id:08d>로 정합니다. WAV, npy, shard 행을 잇는 키입니다.
onset_s / wav_onset_s
타건 시각. onset_s는 세션 시작부터의 초, wav_onset_s는 그 타건 WAV 안에서의 초(keypress 녹음이면 항상 pre_roll_ms/1000 = 0.5).
log-mel / regime
타건 하나를 표현하는 (64, 48) 스펙트로그램. regime은 그걸 만드는 고정 파라미터 묶음(48 kHz, n_fft 1024, …)입니다.
param_hash
regime을 정렬된 JSON으로 만들어 sha256 앞 8자리를 딴 지문. 학습 데이터와 배포 입력의 규격이 같은지 확인하는 데 씁니다.
shard
세션 하나의 로그멜 전부를 담은 mel_packed/<uid>.npz. 수만 개 npy 파일 대신 읽습니다.
keytype
normal(자모) · space · backspace · shift · caps · other. 기호에서 결정됩니다.
top-N coverage
정답이 상위 N개 후보 안에 든 비율. LM 서버가 복구할 수 있는 상한이라 가장 중요한 지표입니다.
ECE / 온도 보정
모델이 말한 확률과 실제 정답률의 차이. 검증 세트에서 온도 T 하나를 맞춰 줄입니다.
PTQ / int8
학습 후 양자화. 대표 샘플 300개로 값 범위를 재서 가중치와 입력을 8비트 정수로 바꿉니다.
게이트 (gate)
kdaa가 단계 사이에서 하는 검사. 걸리면 멈추고 종료 코드 2를 돌려줍니다.

설계 원칙

네 저장소가 공유하는 원칙입니다. 코드를 고칠 때 이 원칙을 깨면 리뷰에서 걸립니다.

  1. 조용히 틀리지 말고 크게 실패한다. 모양이 다른 텐서, 다른 규격으로 만든 로그멜, 손상된 세션은 예외로 멈춥니다. 학습과 배포의 규격이 어긋나면 에러 없이 정확도만 떨어지기 때문입니다(classism NFR-6, AC-8).
  2. 계약은 문서로 고정한다. 저장소 사이의 형식은 spec에 적혀 있고 코드는 거기에 맞춥니다. classism의 spec.md가 "이 문서가 원본이고 코드가 따른다"고 명시합니다.
  3. 모듈은 자기 일만 한다. sound-autodaq는 모듈마다 "맡는 것(Owns)"과 "절대 안 하는 것(Never)"을 docstring에 적어 둡니다(REQ-57). 예를 들어 audio/ 안에 파일을 만드는 곳은 writer.py 하나뿐입니다.
  4. 다시 실행해도 같다. export, Mel, 묶기는 같은 입력이면 같은 파일을 원자적으로 덮어씁니다. 학습은 시드와 분할을 고정하고 split.json을 남깁니다.
  5. 세션 단위로 나눈다. 같은 세션을 학습과 테스트에 섞으면 마이크 위치나 방 소음 같은 세션 특성을 외워서 정확도가 부풀려집니다.
