    시작하기

    개발 환경을 만들고 합성 데이터로 전체 파이프라인을 한 번 돌려 보는 데 10분이면 됩니다. 실제 녹음 장비 없이도 모든 단계가 돌아가도록 만들어져 있습니다.

    환경 만들기Python 3.10 이상

    작업은 kdaa-full-sample 저장소에서 시작합니다. 나머지 세 저장소는 이 저장소의 third_party/ 아래에 git submodule로 들어 있고, 특정 커밋에 고정되어 있습니다. 세 저장소를 따로 받을 필요가 없습니다.

    bash
    git clone --recurse-submodules https://github.com/regx64/kdaa-full-sample
cd kdaa-full-sample
# 이미 받았다면: git submodule update --init

python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install torch --index-url https://download.pytorch.org/whl/cpu   # GPU 머신이면 해당 CUDA 휠
pip install -r requirements.txt
# int8 export까지 하려면 (선택):
pip install -r third_party/classism/requirements-export.txt

    학습 머신은 Windows를 기준으로 합니다. CI가 Linux(Python 3.10, 3.13)와 Windows(3.12)에서 같은 테스트를 돌립니다. 녹음 PC도 Windows가 기준이고, sound-autodaq는 자체 CI에서 Windows 키보드 훅까지 검증합니다.

    첫 실행합성 데이터로 끝까지

    테스트 하나가 합성 녹음 세션 3개를 만들어 녹음 → export → Mel → 묶기 → 검사 → 학습(1 epoch) → 평가 → 리포트까지 돌립니다. 이 테스트가 통과하면 환경이 맞게 잡힌 것입니다. 약 1분 걸립니다.

    bash
    python -m pytest -q                  # kdaa 테스트 10개, test_e2e.py가 전체 흐름
python -m pytest -q tests/test_e2e.py -s --basetemp=/tmp/kdaa-e2e   # 산출물을 남겨서 들여다보기

    실제 녹음으로 돌릴 때는 sound-autodaq로 녹음한 다음 kdaa를 실행합니다.

    bash
    # 1. 녹음 (출력 루트 data/raw 가 pipeline.yaml의 paths.raw 와 같아야 함)
cd third_party/sound-autodaq
python -m experiments.recording --config configs/S01.yaml --dry-run   # 장치·디스크·설정 점검만
python -m experiments.recording --config configs/S01.yaml
cd ../..

# 2. 자동화
python -m kdaa run          # 새/바뀐 세션 처리, 데이터가 바뀌었으면 학습·평가·리포트
python -m kdaa status       # 세션별 단계 상태와 최근 학습 결과
    녹음 출력 경로를 맞추세요sound-autodaq는 output.root(기본 data/raw)를 자기 작업 디렉터리 기준으로 씁니다. 위처럼 third_party/sound-autodaq에서 실행하면 그 안의 data/raw에 쌓입니다. kdaa가 찾게 하려면 설정의 output.root를 kdaa 저장소의 data/raw 절대 경로로 두거나, pipeline.yaml의 paths.raw를 녹음 위치로 바꾸세요.

    읽는 순서

    1. 전체 구조에서 파이프라인 그림과 디렉터리 배치를 봅니다. 어떤 파일이 어느 단계에서 생기는지가 이 코드베이스를 이해하는 열쇠입니다.
    2. 데이터 계약을 읽습니다. 저장소 사이에는 함수 호출이 거의 없고 파일 형식만 오갑니다. 계약을 깨면 다른 저장소가 조용히 틀린 결과를 내므로, 수정 전에 반드시 확인할 부분입니다.
    3. 고칠 저장소의 장(kdaa, sound-autodaq, meligation, classism)에서 모듈별 책임과 확장 지점을 봅니다.
    4. 구체적인 작업은 작업 가이드에 "무엇을 바꾸려면 어느 파일을 고치고 무엇을 다시 돌리나" 형식으로 정리했습니다. 막히면 문제 해결의 증상별 표를 봅니다.
