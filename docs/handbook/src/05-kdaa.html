kdaa — 자동화

세 저장소를 순서대로 호출하고, 세션마다 무엇을 이미 처리했는지 기억하고, 단계 사이에서 데이터를 검사합니다. 계산은 거의 하지 않습니다. 대부분 다른 저장소를 부르는 코드입니다.

언어
Python 3.10+
진입점
python -m kdaa {run,status,watch}
의존성
numpy, PyYAML (+ 세 저장소의 의존성)
설정
pipeline.yaml
테스트
python -m pytest -q · 10개, 약 70초
CI

파일별 책임

파일맡는 일먼저 볼 것
kdaa/stages.py파이프라인 본체. 세션 탐색, 단계별 처리, 지문, 게이트, 학습 재사용 판단Pipeline.run
kdaa/cli.pyrun, status, watch 명령과 종료 코드main

kdaa/mel_shim.pymeligation을 경로로 불러오고, Regime 값을 classism과 비교해 해시를 정한다(임시)open_backend, regime_mismatches
kdaa/pack.py세션의 npy를 shard 하나로 묶는다pack_session
kdaa/report.pyreport.md 작성, 이전 완료 실행과 지표 비교write_report, summarize
kdaa/util.py해시, 원자적 JSON 쓰기, 파일 경로로 모듈 로드(바이트코드 안 씀), git 커밋 조회load_module

코드를 처음 읽는다면 stages.py의 Pipeline.run부터 보세요. 단계 함수를 순서대로 부르는 80줄 정도의 함수라서, 여기서 각 stage_* 메서드로 따라 들어가면 전체가 보입니다.

단계별 동작

1~3은 세션마다, 4 이후는 사용 가능한 세션 전체를 묶어서 한 번 실행합니다. "다시 하는 조건"이 거짓이면 그 단계는 건너뜁니다. --force는 1~3을, --force-train은 학습을 강제합니다.

단계하는 일 (실제 호출)다시 하는 조건보류·멈춤
탐색data/raw 아래 session.json을 모두 찾음. session_summary.json의 completed: true면 완료 세션매번같은 uid가 두 곳에 있으면 멈춤(1). 미완료 세션은 보류
1 exportpython -m experiments.recording --export-classism <세션> --out work (cwd: sound-autodaq)session.json, manifest.jsonl, session_summary.json 내용이나 sound-autodaq 커밋이 바뀜, 또는 CSV가 없음export 실패 시 보류 (오류는 state에)
2 melmeligation build_session을 같은 프로세스에서 호출, _meta.json 기록export 지문, meligation 소스 파일, param_hash 중 하나가 바뀜클립 0개, 또는 건너뛴 비율 > max_skip_rate(1%)면 보류. Regime 값이 다르면 멈춤(1)
3 packpack_session → mel_packed/<uid>.npzmel 지문이 바뀜, 또는 shard가 없음형식이 틀린 npy, NaN/Inf면 예외
4 checkpython -m src.dataset --config work/classism_config.yaml --json work/check.json (cwd: classism)매번종료 코드 3(해시 불일치)이면 멈춤(1). 세션 수 < min_sessions면 멈춤(2). coverage 부족은 참고용 표시(또는 멈춤)
5 trainpython -m src.train --out runs/<id> --config runs/<id>/classism_config.yaml …datahash가 같은 완료 실행이 없음실패 시 run.json status=failed, 멈춤(1)
6 evaluatepython -m src.evaluate --ckpt runs/<id>/best.pt --split test방금 학습했을 때실패 시 멈춤(1)
7 export_int8onnx, onnxruntime, onnx2tf, tensorflow가 있으면 python -m src.export_esp32방금 학습했을 때export.enabled: true인데 도구가 없으면 멈춤(1). auto면 건너뜀
8 reportrun.json 완료 표시, report.md 작성방금 학습했을 때—

지문(fingerprint)

kdaa/stages.py
export_fp = sha256(session.json, manifest.jsonl, session_summary.json, sound-autodaq 커밋)
mel_fp    = sha256(export_fp, meligation 소스 파일 sha256, param_hash)
pack_fp   = sha256(mel_fp, "pack-v1")
datahash  = sha256(정렬된 (uid, pack_fp) 목록, classism_config.yaml 내용,
                   pipeline.yaml의 classism 절, classism 커밋, param_hash)[:8]

지문이 연쇄되어 있어서 export가 다시 돌면 mel과 pack도 따라 다시 돕니다. 다른 저장소의 커밋을 올리면 해당 단계부터 다시 처리됩니다. 학습 실행 디렉터리 이름 끝의 8자리가 datahash입니다.

종료 코드

  • 0 완료, 또는 데이터가 그대로라 이전 실행 재사용
  • 2 게이트에서 멈춤. 세션이 모자라거나 coverage가 부족(설정한 경우). 실패가 아니라 "아직 할 수 없음"
  • 1 실패. 해시 불일치, export/학습/평가 오류, 도구 없음

명령

bash
python -m kdaa [--config pipeline.yaml] run [--until STAGE] [--force] [--force-train]
python -m kdaa status
python -m kdaa watch [--interval 600] [--until STAGE]
run --until
export mel pack check train evaluate export_int8 report 중 하나에서 멈춥니다. 예를 들어 --until check는 학습 없이 데이터만 점검합니다.
status
세션마다 녹음 완료 여부, export 클립 수, Mel 작성/전체, 묶은 클립 수, 보류 이유와 최근 학습 5개를 보여 줍니다. 아무것도 바꾸지 않습니다.
watch
지정한 간격마다 run을 다시 부릅니다. 녹음이 끝난 세션이 생기면 그때 처리되고, 데이터가 그대로면 학습은 건너뜁니다. Ctrl+C로 멈춥니다.

하위 프로세스는 출력을 줄 단위로 화면에 흘려보내고, 학습·평가·export 출력은 runs/<id>/logs/에도 남깁니다. 하위 프로세스 환경에는 PYTHONPATH에 kdaa 루트, PYTHONIOENCODING=utf-8이 들어갑니다(Windows에서 한글 출력이 깨져 죽는 것을 막음).

meligation 임시 보완

kdaa/mel_shim.py는 meligation의 두 문제를 meligation을 고치지 않고 우회합니다. meligation에 정식 수정이 들어오면 이 파일은 아무것도 하지 않게 되고, 그 뒤 지울 수 있습니다.

  1. 파일 이름(B2). 소스가 확장자 없는 code 하나라 import가 안 됩니다. SourceFileLoader로 경로에서 직접 불러옵니다. mel_build.py가 생기면 그쪽을 먼저 씁니다. 모듈 이름에 경로 해시를 붙여 서로 다른 체크아웃을 섞지 않고, __pycache__를 남기지 않습니다.
  2. 해시(B1). meligation 자체 해시가 classism과 같으면 그대로 씁니다. 다르면 regime_mismatches가 11개 값(샘플레이트, n_fft, 창, hop, mel 수, fmin, fmax, 프레임, log_eps, 앞 여유, 클립 길이)과 정규화·dtype을 비교하고, 모두 같을 때만 classism 해시를 기록합니다. 하나라도 다르면 MelRegimeError → Mel 단계 실패.

추출 자체(MelExtractor, build_session)는 meligation 코드 그대로입니다. kdaa는 _meta.json만 다시 씁니다.
