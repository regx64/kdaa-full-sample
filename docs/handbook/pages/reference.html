오디오 형식

sound-autodaq/classism/spec.md
sample_rate  : 48000 Hz
channels     : 1 (mono)
bit_depth    : 16-bit signed linear PCM

sound-autodaq는 녹음 전에 장치가 48 kHz를 그대로 지원하는지 확인하고, 소프트웨어 리샘플링을 하지 않습니다(recording.allow_resample: false). meligation의 load_wav_float는 PCM16이 아니거나 샘플레이트가 다르면 그 클립을 건너뛰고 이유를 _skipped_<session>.csv에 남깁니다. 스테레오가 들어오면 채널 평균으로 모노를 만듭니다.

keypress 녹음(기준 설정)에서는 WAV 하나가 pre_roll_ms + post_roll_ms = 1.0 s이고, 타건은 정확히 0.5 s 지점에 있습니다. Mel은 그중 0.495 ~ 0.595 s의 100 ms만 씁니다. 나머지 앞뒤 여유는 시작점 재정렬과 데이터 변형에 쓰려고 남겨 둔 것입니다.

번호 순서는 위 표 그대로입니다: 자음 14, 된소리 5, 모음 12, Shift 모음 2(=자모 33, 번호 0~32), 그다음 <sp> <bs> <shift> <caps> <other>(33~37). 키 아래 글자는 두벌식에서 그 자모를 내는 물리 키이고, ⇧는 Shift와 함께 누른다는 뜻입니다. 된소리와 ㅒ·ㅖ의 Shift는 같은 타건의 일부로 보고 따로 세지 않습니다.

<other>는 classism에 정의가 없어서 sound-autodaq가 정했습니다. 자모 키, Space, Backspace, Shift, CapsLock, 운영자 숫자키가 아닌 모든 키입니다. 녹음할 때는 반복마다 Enter, Tab, , . / ; ' [ ] - =를 돌아가며 시킵니다.

param_hash는 Regime 데이터클래스를 json.dumps(asdict(r), sort_keys=True, separators=(",", ":"))로 만든 뒤 sha256 앞 8자리를 딴 값입니다. 필드 이름까지 해시에 들어가므로, 값이 모두 같아도 두 저장소의 해시가 다릅니다.

지금은 kdaa의 mel_shim.py가 두 Regime의 값을 항목별로 비교해 모두 같을 때만 _meta.json에 classism 해시를 적습니다. 값이 하나라도 다르면 Mel 단계에서 멈춥니다. 정식 해결은 meligation이 classism과 같은 필드 구성으로 해시를 만드는 것입니다. 그러면 kdaa의 mel_shim.py는 아무 일도 하지 않게 됩니다.

해시가 막지 못하는 것해시는 파라미터 값만 봅니다. 창 함수, 패딩 방식, mel 필터뱅크 공식처럼 구현이 바뀌면 해시는 그대로인데 결과 텐서가 달라집니다. meligation의 추출 코드를 고쳤다면 mel_spec_version을 올리고 학습 데이터를 다시 만들어야 합니다.

classism은 세션마다 shard가 있으면 shard를, 없으면 npy를 읽습니다. 해시는 shard 헤더를 먼저 보고, 없으면 _meta.json을 봅니다. shard 쓰기는 kdaa(kdaa/pack.py), 읽기는 classism(src/dataset.py: read_shard)이 맡고, 둘이 맞는지는 kdaa의 tests/test_pack.py가 classism CLI를 실제로 돌려 확인합니다.

classism 설정 덮어쓰기

kdaa는 학습할 때마다 classism 기본 설정(configs/afe.yaml, 또는 pipeline.yaml의 classism.config)에 아래 세 값을 덮어쓴 YAML을 runs/<id>/classism_config.yaml로 저장하고, 학습·평가·export 모두 --config로 넘깁니다.

runs/<id>/classism_config.yaml (일부)
data:
  min_per_jamo: 25
  min_per_special: 25
  sessions: [P01_S01_SESSION01, P01_S01_SESSION02, P02_S01_SESSION01]   # 보류 세션 제외
  on_missing_mel: drop          # Mel이 건너뛴 행은 빼고 개수만 보고
  require_param_hash: true      # 해시 정보가 없는 세션도 거부

classism 쪽 기본값은 sessions: null(모든 CSV), on_missing_mel: error, require_param_hash: false입니다. classism을 단독으로 쓸 때는 예전처럼 동작합니다.

kdaa.afe.v1분류기 → LM 서버

json
{
  "schema": "kdaa.afe.v1",
  "sample_rate": 48000,
  "session_id": "p1_near_s0",
  "lang": "ko",
  "tokens": [
    { "idx": 0, "onset_s": 1.234, "keytype": "normal",
      "alts": [ {"jamo": "ㄱ", "p": 0.72}, {"jamo": "ㄷ", "p": 0.16}, {"jamo": "ㅋ", "p": 0.12} ] },
    { "idx": 1, "onset_s": 1.402, "keytype": "space",
      "alts": [ {"jamo": "<sp>", "p": 1.0} ] }
  ],
  "meta": { "model_id": "smallcnn-int8-v1", "topN": 5, "input_shape": [1, 64, 48], "calibrated": true }
}
  • tokens는 타건 하나에 하나, 시간 순, idx는 0부터 빈틈없이 이어집니다.
  • alts는 확률 내림차순 상위 N개(기본 5)이고 합이 1이 되도록 다시 나눕니다(AC-9, 허용 오차 1e-6). 확률이 같으면 번호가 작은 클래스가 앞입니다.
  • keytype은 1순위 기호에서 정해집니다. onset_s는 입력에서 그대로 옮깁니다.
  • 분류기는 음절을 만들지 않습니다. 조합, 사전, 언어 모델은 LM 서버 몫입니다(설계 결정 D6).

JSON Schema가 형식을, src/schema.py: validate_document가 스키마로 표현 못 하는 규칙(연속 idx, 확률 합)을 검사합니다.

int8 입력 양자화

ESP32에서는 Mel 출력(float32 로그멜)을 int8로 바꿔서 CNN에 넣습니다. 그 변환에 쓰는 scale과 zero_point는 classism export가 정하고 Mel 펌웨어가 따라야 합니다.

양자화 공식
q = clip(round(x / scale) + zero_point, -128, 127)      # meligation code: quantize_int8
x ≈ (q - zero_point) × scale

값은 runs/<id>/export/deployment.json의 quantization.input에 있고, kdaa가 같은 내용을 runs/<id>/handoff/mel_int8_input.json으로 따로 꺼내 둡니다. 모델을 다시 export하면 값이 바뀔 수 있으므로 펌웨어도 같이 갱신해야 합니다.

meligation 임시 보완

kdaa/mel_shim.py는 meligation의 두 문제를 meligation을 고치지 않고 우회합니다. meligation에 정식 수정이 들어오면 이 파일은 아무것도 하지 않게 되고, 그 뒤 지울 수 있습니다.

  1. 파일 이름(B2). 소스가 확장자 없는 code 하나라 import가 안 됩니다. SourceFileLoader로 경로에서 직접 불러옵니다. mel_build.py가 생기면 그쪽을 먼저 씁니다. 모듈 이름에 경로 해시를 붙여 서로 다른 체크아웃을 섞지 않고, __pycache__를 남기지 않습니다.
  2. 해시(B1). meligation 자체 해시가 classism과 같으면 그대로 씁니다. 다르면 regime_mismatches가 11개 값(샘플레이트, n_fft, 창, hop, mel 수, fmin, fmax, 프레임, log_eps, 앞 여유, 클립 길이)과 정규화·dtype을 비교하고, 모두 같을 때만 classism 해시를 기록합니다. 하나라도 다르면 MelRegimeError → Mel 단계 실패.

추출 자체(MelExtractor, build_session)는 meligation 코드 그대로입니다. kdaa는 _meta.json만 다시 씁니다.
